# 完整 GB2312 字库 / TYP2，2026-10-30

用户目标：换中文歌无需重新生成字库；保留华文琥珀 24px 歌词/歌名、20px 歌手、4bit 覆盖率及现有全部显示功能。支持 GB2312 定义的 7445 个字符（6763 汉字、682 符号）和 ASCII 0x20..0x7E，共 7540 字。不是全 Unicode；LRC1 的编码、488 字记录、64 行等原限制不改变。OSD 幼圆 ROM 不变。

## 文件格式

FONT.HZK 固定 3,856,960 字节 / 964,240 个小端 32bit word。头四字为 0x32505954、0x00141804、964240、7540。后接 8320 个目录项；GB2312 项索引 (区码-0xA1)*94+位码-0xA1，ASCII 项 8178+code-32；未定义项为零。

目录项：[31:28]=0xA，[27:23]=20px 字宽，[22:18]=24px 字宽，[17:0]=相对文件起点的 **16 字节块偏移**。不同于 TYP1 的 word 偏移，旧 bit 不兼容。保留7709个物理字槽（其中169个未定义槽全零），首块2081，每字31块（496字节），末槽首块241029。GB2312区1..9占846槽，区10..15无定义字符整段省略，区16..87占6768槽，ASCII占95槽。物理槽号=目录索引（索引<846）或目录索引-564（其他有效编码）。全部字符直接计算字形地址，运行时无需读取目录。ASCII两字号比例字宽固化为20组10bit组合常量，必须与配套字库逐字匹配。GB2312符号合法编码用9区范围检查；目录保留供PC校验和格式诊断。D7FA..D7FE未定义汉字码拒绝。

每字：24行×12字节（24px/行）+20行×10字节（20px/行）+8字节零填充。每字节高半字节是左像素。ASCII 保留比例字宽，行尾填零。没有图像/灰度有损压缩。

光栅化沿用已批准的字体文件、8倍超采样、字号、基线和LANCZOS。边界外字形仅以最小整数超采样像素平移到格内，禁止裁笔画或缩字；所有 ink 必须在格内。GB2312 A1A4/A1AA 使用该字体自身 U+00B7/U+2014（Windows CP936 对应字形），明确记录映射，禁止缺字方框替代。

## 总线和逐拍契约

text_row_aa的外部端口/CDC不变，clk_sdr=100MHz。所有读请求地址4word对齐，普通读取len=4、跨块字形len=8；req保持到ack，ack后撤销，接收对应4或8个valid并等待done（允许最后valid同拍done）。行跨16字节边界时用一笔8word读取两个块，丢弃行首之前的word，仅保存需要的word；所有字符跳过目录读取，按固定字槽寻址；内部共用32bit字选择器和移位寄存器，避免新增128/256bit桶形移位器。同一笔LRC读中的第二个记录用64bit寄存器暂存供下字复用，每8像素换字，首字可能跳过4个半字节；只有完整行成功才发布。

取消/超时：停止写行缓存；已ack的请求必须排空到done，之后才报告失败。非法头、编码及行范围err=0x66（目录仅由PC素材检查器校验）；短读/超时0x04；取消0x08。末尾字的最后一行不得越过字库范围。丢帧行为沿用layer_text_aa：行截止前取消且不发布部分行。

font_load及公共load_writeback的word计数统一扩至20bit；21bit SDRAM地址保持。byte_len向上取整16B，须检查加法溢出、容量、SDRAM末端；不能在2MiB处回绕。50MHz配置/结束字段在done前稳定，经原toggle邮箱跨100MHz；字节由原异步FIFO跨域。

## 验收

- FULL-01：独立枚举7445+95编码、逐像素解包全部两字号、检查全部LRC45行与包内hash、旧样本文字像素不变。
- FULL-02：RTL取7540字两字号，轮换每行与边界；末字全部行、跨块、空格、ASCII、非法/取消/恢复、8字既有金样。
- FULL-03：真实完整文件经font_load与公共writeback逐字比对，覆盖2MiB边界、末尾、FIFO背压；短文件/越界/加法溢出拒绝。
- FULL-04：图片与字体装载地址和双歌词切换；原背景、封面、音频和OSD回归；行截止与争用不发布错误像素。
- FULL-05：ModelSim编译/仿真后综合、布局布线、STA、bit。旧bit保留；STA未通过时明确记录，不以bit生成冒充时序收敛。
