# 时序清理契约

2026-10-30 用户明确授权：“违例太多了，消除一下”。基线为
`lyricspace_r1_congestion_seed3_phy`，setup 152端点、WNS -6.136ns、hold 0。
新授权开启独立结构修复轮次，保留历史修复记录，初次失败后最多3次自动修复。

1. OSD 保持三像素时钟延迟、所有绘制优先级、16级覆盖率及逐通道精确
   `floor((background*(15-alpha)+foreground*alpha+7)/15)`。
   1024×32同步色表直接替代原末级混色及输出寄存器；无效像素RGB不作保证，valid复位为0。
2. 字符合法性保持完整GB2312和ASCII规则；高低字节比较分别登记，下一既有ADDRESS拍组合。
   不增加每字符时钟数，不改变请求、取消、超时和像素写入协议。
3. 描述符在源SDR域登记合法性，源字段与toggle发布后保持稳定至像素域接收。
   100MHz源域下一拍(10ns)校验完成，25MHz像素域两级toggle检测后采样，保持原提交时刻。
   全宽输入高位必须为零，fc+cnt<=488、cnt非零、歌词<=19，歌名/歌手<=24。
4. 保持五行顶部118/154/190/226/261、24px字格、滚动36相位和三行兼容。
5. 不降低时钟、不添加时序例外、不移除SDRAM移相接口检查。以最终布局布线报告验收；
   仿真通过、bit生成不能替代STA或实板验证。
6. R2：选句槽合法性保留全16位fc/cnt拒绝规则，在高位校验后用10位和判断488边界。
   仲裁器在请求接受拍预计算clamp(len)-1（零长饱和0），RUN用n>=last_n替代n+1>=len；
   不改变使能、地址、FWFT数据、暂停恢复、优先级、done或沉降拍数。
   时间比较每拍登记，仅在原DIRECTORY拍消费；不新增取字周期。
   新增仲裁器与R1原RTL逐拍差分：MAX_BURST=0/2048/65535、0..7/16/2048/2049/65535长度、
   三客户端、刷新暂停、地址回绕及同时请求；选句385组合法/非法边界，六槽全部检查。
7. R2最终123个setup端点，因入口减法/比较及拥塞退化，不交付该版本。
   R3以一位terminal_q替代16位last_n：接受拍登记clamp(len)<=1；每个未暂停RUN拍
   登记17位n+2>=len，供下个RUN拍结束判断；刷新暂停/恢复时保持该位和n。
   可达RUN拍保持terminal_q等价原16位n+1>=len；65535长度的最终n为65534，不会回绕。
   原逐拍差分用同一参考重跑，不修改断言和预期。

验收复用带独立逐像素参考的OSD/core、全7540字、异常/恢复、五行含真实SDRAM争用、
旧三行文字层和板级展开测试。源文件、ROM、工具脚本哈希纳入构建及验证证据。
